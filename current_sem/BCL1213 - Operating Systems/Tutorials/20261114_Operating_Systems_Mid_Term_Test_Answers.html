Question 1 (25 Marks)

(a) Definition of Operating Systems Fundamentals (3 Marks)

An Operating System (OS) is core system software that acts as an intermediary bridge between computer hardware and user application software (Silberschatz et al., 2018). It abstracts complex, low level hardware operations into manageable abstractions while orchestrating the hardware resources of the machine. The fundamental roles of an operating system can be synthesized into three primary responsibilities:

  1. Resource Management: The operating system allocates and deallocates central processing unit time, main memory regions, input and output peripherals, and storage blocks among competing tasks to maximize efficiency and avoid conflict.
  2. Hardware Abstraction and Control: By utilizing device drivers and kernel interfaces, the operating system conceals physical architecture nuances from user programs, providing standardized system calls for file manipulation, network transmission, and hardware interaction.
  3. Execution Environment and Protection: The operating system supervises process execution in protected dual mode operations (user mode and kernel mode). This ensures isolated execution spaces, preventing malfunctioning or unauthorized applications from crashing adjacent programs or compromising the underlying system.

(b) Layered Interaction in Operating Systems to Maximize Multiprogramming (9 Marks)

The degree of multiprogramming reflects the total number of distinct active processes simultaneously resident within primary memory competing for processor cycles. Layer Interactions and Workflow

  1. User to Application Layer: Multiple users or automated user sessions invoke concurrent software applications, including database engines, web browsers, and media editors. Each invocation spawns execution requests that pass downward into the application environment.
  2. Application to Operating System Layer: Applications cannot directly manipulate physical memory or hardware registers due to kernel protection barriers. When an application requires system resources, such as allocating memory, opening a socket, or reading a storage file, it invokes a System Call (POSIX or Windows API). This triggers a software interrupt or trap that transitions processor execution from unprivileged user mode to privileged kernel mode.
  3. Operating System to Hardware Layer: Inside kernel space, specialized subsystems, including the CPU scheduler, virtual memory manager, and device driver modules, translate logical requests into hardware operations. The OS issues commands to device controllers and assigns CPU time slices through hardware timer interrupts.
  4. Hardware to Operating System Layer: As hardware devices execute asynchronous tasks (such as disk sector reads or packet arrivals), controllers fire hardware interrupts back to the CPU. The operating system interrupt handler halts current execution temporarily, saves processor registers, processes the completed I/O transaction, and updates process states.

Maximizing the Degree of Multiprogramming

The architectural coordination among these layers maximizes the degree of multiprogramming through four interrelated operational mechanisms:

  1. Overlapping CPU and I/O Execution: Central processing units operate at nanosecond speeds, whereas disk and network peripherals operate at millisecond timescales. When an active application issues an I/O system call, the operating system immediately transitions that process from the Running state to the Waiting state. Instead of permitting the processor to stall idle, the short term scheduler dispatches another ready process from the memory resident queue.
  2. Memory Multiplexing and Isolation: The memory management subsystem partitions physical RAM to house multiple process address spaces concurrently. By leveraging hardware paging and base limit registers, the operating system guarantees that several applications remain co-resident in memory without risk of memory overwrites.
  3. Preemptive Time Slicing via Hardware Timers: Hardware interval timers generate periodic interrupts that return CPU control to the kernel dispatcher. The operating system enforces round robin or multi level feedback scheduling, preventing any single compute heavy process from monopolizing the processor, thereby preserving high responsiveness across all co-resident tasks.
  4. Interrupt Driven I/O Asynchrony: Upon I/O completion, hardware interrupts trigger the operating system to move waiting applications back to the Ready queue. This bidirectional loop ensures that processor utilization approaches saturation while maintaining high overall system throughput.

(c) Differentiating Internal and External Fragmentation (4 Marks)

Memory fragmentation occurs when available physical memory cannot be effectively utilized by arriving processes. The distinction between internal and external fragmentation relates to where the unallocated memory resides and the architectural allocation policy responsible.

Comparative Aspect Internal Fragmentation External Fragmentation
Location of Unused Memory Resides inside an allocated memory block or partition assigned to a specific process. Resides outside allocated partitions, scattered across memory as unallocated holes.
Primary Root Cause Arises from fixed-size allocation units (such as fixed partitioning or paging) when a process request is smaller than the assigned block size. Arises from dynamic, variable-size contiguous allocation as processes of varying sizes load and terminate over time.
Availability to Other Processes The wasted space is locked within the partition and cannot be used by any other process until the current process terminates. Total free memory across all holes may be mathematically sufficient for a new job, but no single contiguous hole is large enough.
Remediation Techniques Employing smaller block/page sizes, dynamic memory allocation, or variable segment sizing. Memory compaction (relocating active partitions dynamically) or transitioning to non-contiguous paging schemes.

(e) Advantages of Multiprogramming (3 Marks)

Multiprogramming delivers several systemic performance advantages over uniprogramming execution environments:

  1. High Central Processing Unit Utilization: In a uniprogramming system, the processor sits completely idle while a process performs slow peripheral I/O operations. Multiprogramming allows the operating system to switch the CPU to an alternate ready job, keeping CPU utilization consistently elevated.
  2. Improved Total System Throughput: System throughput, measured as the number of completed jobs per unit time, increases substantially because computational processing and peripheral device transfers proceed in parallel across distinct programs.
  3. Decreased Turnaround and Response Latencies: Shorter or interactive jobs do not experience starvation behind massive batch calculations, because shared processor scheduling guarantees equitable execution progress across all active tasks.

Question 2 (25 Marks)

(a) Definition and Mechanism of Swapping (3 Marks)

Swapping is a memory management mechanism wherein an entire process address space (or inactive pages of a process) is temporarily evacuated from primary physical memory (RAM) and stored onto a fast secondary backing store, such as a dedicated disk swap partition or solid state drive swapfile (Tanenbaum & Bos, 2015).

The operating system executes swapping via a mid term scheduler. When physical memory becomes overcommitted, the mid term scheduler selects a dormant, blocked, or low priority process, copies its active execution image and register context to secondary storage, and marks its physical frames as free. When the process is scheduled to resume or when sufficient RAM becomes available, the swapper reads the memory image back from the backing store into available physical memory frames, updates internal address mapping tables, and returns the process to the Ready queue.

(b) Two Reasons Why the Operating System Performs Swapping in the Laboratory Scenario (4 Marks)

  1. Relieving Memory Overcommitment and Preventing System Depletion: The laboratory environment executes concurrent high demand workloads, specifically a database management system, a multi tab web browser, and a video editing suite. Because the aggregate memory footprint of these applications exceeds the physical RAM limits, swapping evacuates idle or background processes to secondary storage, preventing out-of-memory kernel panics and preserving system stability.
  2. Facilitating Fair Multitasking and Priority Execution: Video rendering and interactive database querying require substantial working sets to execute without interruption. Swapping enables the operating system to temporarily suspend lower priority background tasks, such as inactive browser instances, allocating uncontested physical RAM to the active foreground processes to maintain high interactive performance.

(c) Swapping Out and Swapping In: Process and Impact on Execution (5 Marks)

Operational Process

  • Swapping Out: The mid term scheduler identifies a victim process (e.g., an application blocked on long term user input). The kernel writes the execution state, data segments, heap, and thread stacks of the process onto the secondary swap space. The memory management unit updates page and segment descriptors to mark the locations as invalid or swapped out, liberating the physical RAM frames for other active processes.
  • Swapping In: When a swapped process receives a pending event or is selected by the scheduler, the operating system allocates free physical memory frames. If RAM is full, another process must first be swapped out. The kernel transfers the saved memory blocks from secondary storage into the newly allocated frames, reconfigures page table base registers and translation entries, and transitions the process back to the Ready state.

Effects on Process Execution

Swapping imposes a notable latency penalty on process execution. Secondary storage transfer speeds, even on modern solid state drives, remain several orders of magnitude slower than bus speeds in physical RAM. Consequently, a process undergoing swapping experiences execution suspension, during which it cannot make computational progress. If physical memory is chronically undersized, the system risks thrashing, a state in which the processor spends more time moving pages between RAM and disk than executing user instructions.

(d) Two Fundamental Principles or Challenges of Concurrency in the Laboratory Scenario (6 Marks)

  1. Race Conditions: A race condition manifests when multiple concurrent execution threads or processes access and manipulate shared data items simultaneously, such that the final outcome depends unpredictably on the precise execution order and timing of thread scheduling (Silberschatz et al., 2018). In the university laboratory scenario, concurrent database transactions updating the same laboratory inventory or student account records without synchronization will produce corrupt, inconsistent records due to interleaved read, modify, and write sequences.
  2. Deadlock: Deadlock represents an execution impasse where two or more processes are unable to proceed because each holds a non shareable resource while awaiting another resource held by the competing process. For instance, the video editing application may hold an exclusive hardware lock on the GPU frame buffer while requesting access to a shared database transaction log, whereas the database server holds the lock on the transaction log while requesting the frame buffer. If mutual exclusion, hold and wait, no preemption, and circular wait conditions converge, all involved processes freeze indefinitely.

(e) Preventing Inconsistent Account Balances Using Critical Sections and Mutual Exclusion (4 Marks)

In concurrent systems, the code segment that reads, modifies, and writes back shared mutable data (such as a database bank balance variable) is designated as the Critical Section.

To prevent inconsistent balances, the operating system and database management system enforce Mutual Exclusion. Mutual exclusion guarantees that when one process enters its critical section to manipulate a shared account balance, all other competing processes are strictly prohibited from entering their respective critical sections for that same data item.

Operational Mechanism

Consider an initial balance of $1,000 subjected to two concurrent transactions: Transaction A deposits $200, and Transaction B withdraws $100. Without mutual exclusion, both transactions read $1,000 simultaneously. If Transaction A calculates $1,200 and Transaction B calculates $900, the last transaction to write back overwrites the other update, causing a lost update anomaly.

By enforcing mutual exclusion using synchronization locks:
1. Transaction A acquires the mutual exclusion lock protecting the account record, enters the critical section, reads $1,000, updates the balance to $1,200, writes the record, and releases the lock.
2. Transaction B is forced to wait in a queue until the lock is released.
3. Transaction B acquires the lock, enters the critical section, reads the accurate balance of $1,200, computes $1,100, writes the final state, and exits.

Mutual exclusion converts concurrent overlapping data access into an orderly, serial execution sequence, guaranteeing transactional atomicity and data consistency.

(f) Consequence of Poor Concurrency Control and Appropriate Solution (3 Marks)

  • Consequence (The Lost Update Anomaly): When concurrent processes update shared database records without synchronization, the lost update anomaly occurs. One process reads an uncommitted value, modifies it in local registers, and writes it back, completely erasing an intermediate update performed by an interleaved process. This causes permanent ledger corruption, unrecoverable data discrepancies, and financial inaccuracies.
  • Recommended Solution: Implementation of Strict Two-Phase Locking (2PL) combined with Mutex Locks or Atomic Database Transactions. Under two phase locking, a transaction must acquire exclusive write locks on all records before modifying data, and cannot release locks until transaction commit. This satisfies ACID properties (Atomicity, Consistency, Isolation, Durability), preventing data races and guaranteeing serializable consistency.

Detailed Transition Explanations

  1. New to Ready (Admit): The long term job scheduler creates the Process Control Block and admits the newly created program into main memory, assigning it a slot in the ready queue.
  2. Ready to Running (Dispatch): The short term CPU scheduler selects the process from the ready queue according to scheduling policy and allocates the CPU via context dispatching.
  3. Running to Ready (Interrupt): The executing process is preempted by the operating system due to the expiration of its allocated time slice quantum or the arrival of a higher priority process.
  4. Running to Waiting (Block): The running process requests an operating system service that cannot be completed immediately, such as an I/O peripheral transfer or child process synchronization, moving to the waiting queue.
  5. Waiting to Ready (Wakeup): The requested I/O transfer completes or an asynchronous event signal arrives. An interrupt notifies the operating system, which transitions the process back to the ready queue.
  6. Running to Terminated (Exit): The process executes its final instruction, makes an exit system call, or encounters an unrecoverable runtime error, prompting the operating system to reclaim its resources.

(c) Five Information Fields Stored in a Process Control Block (5 Marks)

The Process Control Block (PCB) is the primary kernel data structure that stores the complete operational state of an operating system process (Stallings, 2018). Five key fields include:

  1. Process Identifier (PID) and Process State: A unique numerical identifier assigned by the kernel to reference the process, accompanied by its current execution status (New, Ready, Running, Waiting, or Terminated).
  2. Program Counter (PC): A processor register pointer that records the exact memory address of the next machine instruction to be executed when the process regains CPU control.
  3. CPU Register Save Area: Storage for hardware accumulators, index registers, stack pointers, and condition code flags that must be saved during an interrupt so execution can be restored seamlessly.
  4. CPU Scheduling Information: Contains the scheduling priority level of the process, pointers to active scheduling queues, and historical metrics such as consumed CPU time slices.
  5. Memory Management Information: Holds base and limit register values or pointers to page tables and segment tables, allowing the memory management unit to validate and translate logical addresses during execution.

Operational Steps of a Context Switch from Process P1 to Process P2

A context switch represents the kernel mechanism used to reassign the central processing unit from an active process (P1) to another waiting process (P2).

  1. Hardware Interrupt or System Call: While P1 executes in user mode, a hardware timer interrupt or system call trap occurs, switching processor privilege to kernel mode.
  2. Saving the Context of P1: The kernel saves P1's current architectural state, including the Program Counter, general purpose registers, floating point registers, stack pointer, and processor status word, directly into P1's PCB.
  3. Updating Process State and Queue Relocation: P1's state is changed from Running to Ready (if preempted) or to Waiting (if blocked on I/O). PCB1 is enqueued into the corresponding scheduling list.
  4. Process Selection: The CPU scheduler executes its scheduling algorithm (such as Round Robin or Priority Scheduling) to select the next process, P2, from the ready queue.
  5. Memory Context Reconfiguration: The kernel switches the virtual memory translation context by updating the page table base register (such as register CR3 on x86 architectures) to point to P2's page tables, invalidating non global Translation Lookaside Buffer (TLB) cache lines.

  7. Resuming Execution: The operating system executes a return from interrupt instruction, dropping CPU privilege back to user mode and resuming P2 at its saved program counter location.

Necessity in a Multiprogramming Environment

  1. Enabling Time Sharing and Concurrency: Context switching allows a single physical processor core to be shared among dozens of active processes, creating the working illusion of simultaneous execution for end users.
  2. Preventing Processor Underutilization: When an executing process stalls on high latency peripheral transfers, context switching immediately reassigns the processor to a compute ready process, keeping hardware throughput near saturation.
  3. Enforcing Equitable Scheduling and Responsiveness: Without preemptive context switching, a compute intensive batch process could run indefinitely, starving interactive tasks and degrading overall responsiveness.

(a) The Concept of Paging in Memory Management (5 Marks)

Paging is a non contiguous memory allocation architecture that decouples a program's logical address space from physical memory (RAM), eliminating external fragmentation and avoiding the need for compaction.

  • Page: The fixed size logical partition of a process's virtual address space. Programs are subdivided into equal sized pages during compilation and loading.
  • Frame: The fixed size physical partition of physical RAM. Frames are configured to match the exact size of logical pages.
  • Page Table: A kernel maintained data structure for each process that stores the mapping between logical page numbers and physical frame numbers, augmented with protection flags, valid invalid bits, and dirty bits.

Translation Mechanics

When the CPU generates a logical address, the Memory Management Unit divides the address into a Page Number ($p$) and a Page Offset ($d$). The page number indexes the process page table to retrieve the assigned physical frame number ($f$). Because page size and frame size are identical, the offset within the page translates directly to the offset within the frame. The physical memory address is formed by concatenating the frame number with the offset ($\text{Physical Address} = f \times \text{Page Size} + d$).

(b) Memory System Calculations and Structural Relationships (11 Marks)

Given System Specifications

  • Logical Address Space: $16\text{ KB} = 16 \times 1,024\text{ bytes} = 16,384\text{ bytes} = 2^{14}\text{ bytes}$
  • Physical Memory: $64\text{ KB} = 64 \times 1,024\text{ bytes} = 65,536\text{ bytes} = 2^{16}\text{ bytes}$
  • Page Size: $4\text{ KB} = 4 \times 1,024\text{ bytes} = 4,096\text{ bytes} = 2^{12}\text{ bytes}$

(i) Number of Pages in the Logical Address Space (3 Marks)

The total number of logical pages is calculated by dividing the logical address space by the page size:

$$\text{Number of Pages} = \frac{\text{Logical Address Space}}{\text{Page Size}} = \frac{16\text{ KB}}{4\text{ KB}} = 4\text{ pages}$$

Binary Address Breakdown
  • Total logical address bits: $\log_2(16,384) = 14\text{ bits}$.
  • Offset bits ($d$): $\log_2(\text{Page Size}) = \log_2(4,096) = 12\text{ bits}$.
  • Page number bits ($p$): $\text{Total Bits} - \text{Offset Bits} = 14 - 12 = 2\text{ bits}$.
  • Valid page numbers: $2^2 = 4\text{ pages}$ (Page 0, Page 1, Page 2, Page 3).

(ii) Number of Frames in Physical Memory (3 Marks)

The total number of physical frames is calculated by dividing physical memory capacity by the frame size (which is equal to page size):

$$\text{Number of Frames} = \frac{\text{Physical Memory Size}}{\text{Frame Size}} = \frac{64\text{ KB}}{4\text{ KB}} = 16\text{ frames}$$

Binary Address Breakdown
  • Total physical address bits: $\log_2(65,536) = 16\text{ bits}$.
  • Offset bits ($d$): $\log_2(4,096) = 12\text{ bits}$.
  • Frame number bits ($f$): $\text{Total Physical Bits} - \text{Offset Bits} = 16 - 12 = 4\text{ bits}$.
  • Valid frame numbers: $2^4 = 16\text{ frames}$ (Frame 0 through Frame 15).

(iii) Relationship Between Pages and Frames (5 Marks)

  1. Dimensional Equivalence: Pages and frames maintain identical physical dimensions ($4\text{ KB} = 4,096\text{ bytes}$). This guarantees that any logical page can occupy any free physical frame without translation scaling.
  2. Logical to Physical Decoupling: Pages represent the process perspective of contiguous linear address space, whereas frames represent actual hardware memory blocks. A program with 4 logical pages requires only 4 frames out of the 16 available in physical memory.
  3. Non-Contiguous Allocation: Logical pages that appear consecutive in program memory (e.g., Pages 0, 1, 2, and 3) can be scattered across non-contiguous physical frames (such as Frames 1, 5, 8, and 14).
  4. Independent Address Spaces: The total number of pages ($4$) is smaller than the total number of physical frames ($16$). The remaining 12 physical frames ($48\text{ KB}$) can be allocated to other concurrent processes or reserved for operating system kernel buffers.
  5. Indirection via Page Table: The page table serves as the translation link. The offset bits ($12\text{ bits}$) pass through unchanged from logical address to physical address, while the $2\text{ bit}$ page number is mapped to a $4\text{ bit}$ frame number.

(c) Concept of Segmentation and Differentiation from Paging (5 Marks)

Concept of Segmentation

Segmentation is a variable size memory management scheme that aligns with the programmer view of software structure (Silberschatz et al., 2018). Instead of dividing a program into arbitrary fixed size blocks, segmentation partitions memory into variable length logical modules, such as the main function, global data segment, runtime heap, thread stack, and library routines.

A logical address under segmentation comprises a pair: $\langle\text{Segment Number } s, \text{Offset } d\rangle$. The operating system maintains a Segment Table, where each entry contains a Base Address (the starting physical memory location of the segment) and a Limit (the exact length of the segment). When the CPU executes an instruction, the hardware validates that the offset is strictly less than the segment limit ($d < \text{Limit}$). If valid, the physical address is computed as $\text{Physical Address} = \text{Base} + d$; otherwise, a memory access violation trap (segmentation fault) is raised.

(d) Role of Virtual Memory in Executing Large Programs on Limited RAM (4 Marks)

Virtual memory enables an operating system to execute programs whose aggregate address spaces exceed available physical RAM through three operational mechanisms:

  1. Separation of User Logical Memory from Physical Memory: Virtual memory abstracts physical RAM into an expansive virtual address space, allowing programs that require substantial memory to execute on constrained physical hardware without manual memory overlaying by programmers.
  2. Demand Paging and Working Set Execution: Under demand paging, programs are not loaded into RAM in their entirety at launch. Instead, pages are transferred from secondary storage into physical frames only when referenced during execution. Because programs exhibit temporal and spatial locality, only the active execution set (the working set) must reside in physical RAM at any given moment.
  3. Page Fault Resolution and Dynamic Page Replacement: When the processor attempts to access a virtual address mapped to an unallocated page, the hardware MMU detects an invalid bit and raises a Page Fault Interrupt. The operating system kernel intercepts the trap, suspends the executing process, loads the requested page from backing storage into an available frame, updates the page table, and restarts the instruction. If physical memory is completely occupied, a page replacement algorithm (such as Least Recently Used or Clock) selects an inactive victim page, writes modified contents back to disk, and repurposes the frame.
