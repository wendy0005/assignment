## How to revise

1. Read one chapter in the guide. Close it and explain the main ideas aloud in your own words.
2. Use the matching flashcards. Mark cards you cannot explain without looking.
3. Solve scheduling and memory questions on paper. Show the timeline, formula, units and intermediate calculations.
4. Take the quiz without notes. For every mistake, write why your choice was wrong and why the correct answer works.
5. Re-test missed concepts the next day. Use the infographic as a recall prompt, then return to the guide if you cannot explain a label.

### Flexible three-session plan

- Session 1: Chapters 1–2; practise process-state transitions, PCB versus process, and scheduling calculations.
- Session 2: Chapter 3; compare memory techniques and practise address translation and fragmentation questions.
- Session 3: Chapter 4; trace race conditions, compare synchronization tools, explain the four deadlock conditions, then attempt a mixed quiz.

Split a session across several days if needed. These are revision suggestions, not predictions of exam questions or marks.

## Exam calculation checks

- Turnaround time = completion time − arrival time.
- Waiting time = turnaround time − CPU burst time for the usual single-CPU-burst exercises; account separately for I/O if a question includes it.
- Response time = first CPU start time − arrival time.
- State whether scheduling is preemptive; identify the Round Robin quantum and tie-breaking rule where relevant.
- Paging: page number = integer quotient of logical address / page size; offset = remainder. Physical address = frame number × page size + offset.
- Segmentation: an offset is valid only when `0 ≤ offset < segment limit` (when limit denotes segment length). Then physical address = base + offset.
- Concurrency may interleave on one core; parallel execution needs simultaneous execution resources.
- Correct mutual exclusion does not by itself guarantee freedom from deadlock or starvation.
