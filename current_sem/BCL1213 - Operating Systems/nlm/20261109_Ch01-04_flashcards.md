## Card 1

**Question:** [Chapter 1 - Intro to OS] What is an Operating System (OS)?

**Answer:** An Operating System is system software that manages computer hardware and software resources, serving as an intermediary between user applications and system hardware.

---

## Card 2

**Question:** [Chapter 1 - Intro to OS] Why is an Operating System described as a 'resource manager'?

**Answer:** It allocates system resources (such as CPU time, memory, storage, and I/O devices) effectively and fairly to maximize performance and maintain system stability.

---

## Card 3

**Question:** [Chapter 1 - Intro to OS] What is the correct hierarchy flow when an application requests access to physical hardware?

**Answer:** Application $\rightarrow$ Operating System $\rightarrow$ Device Driver $\rightarrow$ Hardware

---

## Card 4

**Question:** [Chapter 1 - Intro to OS] What is the primary function of a device driver in an operating system?

**Answer:** A device driver translates high-level common requests from the operating system into specific hardware commands tailored to underlying physical components.

---

## Card 10

**Question:** [Chapter 1 - Intro to OS] What defines a Real-Time Operating System (RTOS)?

**Answer:** An OS designed to process continuous incoming data and respond within strict, predictable time constraints.

---

## Card 11

**Question:** [Chapter 1 - Intro to OS] How does a Hard RTOS differ fundamentally from a Soft RTOS?

**Answer:** In a hard real-time system, missing a required deadline is unacceptable and may have serious consequences. A soft real-time system tolerates some missed deadlines with reduced service quality; a missed deadline does not necessarily cause total system failure.

---

## Card 12

**Question:** [Chapter 1 - Intro to OS] Why is a Batch Operating System unsuitable for an automated air-traffic monitoring system?

**Answer:** Batch systems collect and process jobs sequentially in groups without real-time interaction, preventing immediate response to critical sensory updates.

---

## Card 13

**Question:** [Chapter 1 - Intro to OS] In real-time computing, why is 'fast processing' alone insufficient to describe system requirements?

**Answer:** Real-time performance requires determinism and predictable timing guarantees, not merely high average execution speeds.

---

## Card 14

**Question:** [Chapter 1 - Intro to OS] What are the primary features and typical use cases of Tertiary Storage?

**Answer:** Tertiary storage consists of very slow, very large capacity, low-cost non-volatile storage (e.g., optical discs, tape drives) used mainly for long-term archiving and backups.

---

## Card 15

**Question:** [Chapter 1 - Intro to OS] How does Secondary Storage differ from Main Memory (RAM) regarding data volatility?

**Answer:** Secondary storage is non-volatile (retains data when powered off), whereas main memory (RAM) is volatile (loses data when power is lost).

---

## Card 16

**Question:** [Chapter 2 - Process Management] What is the core distinction between a program and a process?

**Answer:** A program is a static set of instructions stored on disk; a process is a dynamic program in execution loaded into memory with active execution state.

---

## Card 17

**Question:** [Chapter 2 - Process Management] What is the role of the Program Counter (PC) component within a process?

**Answer:** It holds the memory address of the next instruction to be executed by the CPU for that process.

---

## Card 18

**Question:** [Chapter 2 - Process Management] In process memory structure, how does the Stack section differ from the Heap section?

**Answer:** The Stack stores temporary execution data such as function parameters, return addresses, and local variables; the Heap stores memory dynamically allocated during execution.

---

## Card 19

**Question:** [Chapter 2 - Process Management] What is a Process Control Block (PCB)?

**Answer:** A data structure maintained by the OS containing key metadata about a process, including PID, process state, program counter, CPU registers, and memory management info.

---

## Card 20

**Question:** [Chapter 2 - Process Management] What occurs during the 'Start' (or 'New') state of a process lifecycle?

**Answer:** The operating system creates the process, assigns its process control block, and sets up its initial resource structures.

---

## Card 21

**Question:** [Chapter 2 - Process Management] What condition defines the 'Ready' state in process management?

**Answer:** A ready process can run as soon as it is given CPU time; it is not waiting for an I/O event. The simple course model assumes it is resident in main memory.

---

## Card 22

**Question:** [Chapter 2 - Process Management] What causes a running process to move into the 'Waiting' (or 'Blocked') state?

**Answer:** The process cannot proceed until a specific external event occurs, such as completing an I/O operation or disk read.

---

## Card 23

**Question:** [Chapter 2 - Process Management] Which state transition occurs when a process in the 'Running' state requires an I/O operation?

**Answer:** The process transitions from 'Running' to 'Waiting'. After I/O completion, it moves to 'Ready'.

## Card 24

**Question:** [Chapter 2 - Process Scheduling] What is the main responsibility of the Long-Term Scheduler (Job Scheduler)?

**Answer:** It selects processes from the mass storage job pool, loads them into main memory, and controls the degree of multiprogramming.

---

## Card 25

**Question:** [Chapter 2 - Process Scheduling] What is the primary function of the Short-Term Scheduler (CPU Scheduler)?

**Answer:** It frequently selects which ready process in memory gets CPU execution time next.

---

## Card 26

**Question:** [Chapter 2 - Process Scheduling] What is the role of the Medium-Term Scheduler?

**Answer:** It handles process swapping by temporarily suspending and moving idle/inactive processes out of main memory to optimize resource utilization.

---

## Card 27

**Question:** [Chapter 2 - Process Scheduling] What is meant by the term 'degree of multiprogramming'?

**Answer:** The total number of processes residing simultaneously in main memory.

---

## Card 28

**Question:** [Chapter 2 - Process Management] What is context switching, and why is frequent context switching undesirable?

**Answer:** Context switching is saving the CPU state of a current process and restoring another process's state. Frequent context switching creates purely administrative CPU overhead without executing user code.

---

## Card 29

**Question:** [Chapter 2 - Process Scheduling] What is the formula for process Turnaround Time (TAT)?

**Answer:** $\text{Turnaround Time (TAT)} = \text{Completion Time} - \text{Arrival Time}$

---

## Card 30

**Question:** [Chapter 2 - Process Scheduling] What is the formula for process Waiting Time (WT)?

**Answer:** $\text{Waiting Time (WT)} = \text{Turnaround Time} - \text{Burst Time}$

---

## Card 31

**Question:** [Chapter 2 - Process Scheduling] How does the First-Come, First-Served (FCFS) algorithm determine CPU allocation?

**Answer:** It allocates the CPU to processes strictly in the order of their arrival in the ready queue.

---

## Card 32

**Question:** [Chapter 2 - Process Scheduling] What is the 'convoy effect' associated with FCFS scheduling?

**Answer:** A scenario where short processes wait in queue for a long CPU-bound process to finish, significantly increasing average waiting time.

---

## Card 33

**Question:** [Chapter 2 - Process Scheduling] How does Shortest Job Next (SJN / SJF) scheduling select the next process?

**Answer:** It selects the process with the smallest execution burst time from the ready queue.

---

## Card 34

**Question:** [Chapter 2 - Process Scheduling] What potential disadvantage is associated with Shortest Job First (SJF) scheduling?

**Answer:** Starvation: longer jobs may be delayed indefinitely if short processes continuously enter the ready queue.

---

## Card 35

**Question:** [Chapter 2 - Process Scheduling] How does Round Robin (RR) CPU scheduling operate?

**Answer:** It assigns CPU execution time to each process for a fixed interval called a time quantum, cycling through ready queue processes.

---

## Card 36

**Question:** [Chapter 2 - Process Scheduling] What is the consequence of selecting a very small time quantum in Round Robin scheduling?

**Answer:** It causes frequent context switching, which increases system overhead and reduces overall CPU efficiency.

---

## Card 37

**Question:** [Chapter 2 - Process Scheduling] How does Priority Scheduling decide execution order?

**Answer:** Each process is assigned a priority rank; the CPU is allocated to the process with the highest priority.

---

## Card 38

**Question:** [Chapter 2 - Process Scheduling] How does the 'aging' technique solve process starvation in priority systems?

**Answer:** Aging continuously increases the priority ranking of processes that remain waiting in the system for extended periods.

---

## Card 39

**Question:** [Chapter 2 - Process Architecture] Why do modern web browsers like Chrome run individual tabs as separate processes rather than single threads?

**Answer:** Separate renderer processes provide isolation, so a crash or compromise is less likely to affect other renderers. A browser does not necessarily assign exactly one process to each tab.

---

## Card 40

**Question:** [Chapter 2 - Process Architecture] What structural feature distinguishes threads within a single process from separate processes?

**Answer:** Threads in one process share its address space and many resources, but have their own registers and stacks. Separate processes have distinct address spaces, although they can explicitly share memory.

## Card 49

**Question:** [Chapter 4 - Process Synchronization] What is concurrency in operating systems?

**Answer:** A system state where multiple processes or threads execute simultaneously or in overlapping time periods.

---

## Card 50

**Question:** [Chapter 4 - Process Synchronization] What is a race condition?

**Answer:** A concurrency flaw where multiple threads access shared resources without synchronization, making final results dependent on execution timing.

---

## Card 51

**Question:** [Chapter 4 - Process Synchronization] Suppose an initial bank balance is RM1,000. Thread A deposits RM100 and Thread B withdraws RM200 concurrently without synchronization. Why can the final balance result in RM800?

**Answer:** Thread B performed an unprotected read of RM1,000 before Thread A wrote RM1,100. Thread B calculates $1000 - 200 = 800$ and overwrites the balance, resulting in a lost deposit.

---

## Card 52

**Question:** [Chapter 4 - Process Synchronization] What is a critical section in process execution?

**Answer:** A critical section is code that accesses shared state requiring coordination. A mutual-exclusion mechanism prevents conflicting accesses from overlapping.

---

## Card 53

**Question:** [Chapter 4 - Process Synchronization] What is a Mutex (Mutual Exclusion) lock?

**Answer:** A synchronization locking mechanism used to guarantee that only one process or thread enters a critical section at any single moment.

---

## Card 54

**Question:** [Chapter 4 - Process Synchronization] What is a Semaphore in process coordination?

**Answer:** A signaling variable/tool used to control access to finite shared resources across multiple concurrent processes.

---

## Card 55

**Question:** [Chapter 4 - Process Synchronization] What defines a Deadlock state?

**Answer:** A situation where two or more processes are permanently blocked because each is waiting for a resource held by another process in a circular chain.

---

## Card 56

**Question:** [Chapter 4 - Process Synchronization] What is Starvation in process management?

**Answer:** A condition where a ready process is delayed indefinitely from acquiring resources because other higher-priority tasks continuously take precedence.

---

## Card 57

**Question:** [Chapter 4 - Process Synchronization] What is the key functional difference between Deadlock and Starvation?

**Answer:** Deadlock blocks a set of processes because of circular resource dependencies; unrelated processes may continue. Starvation means a process waits indefinitely while other processes continue to obtain service.

---

## Card 58

**Question:** [Chapter 4 - Process Synchronization] What are the four necessary conditions for a deadlock to occur?

**Answer:** 1. Mutual Exclusion
2. Hold and Wait
3. No Preemption
4. Circular Wait

---

## Card 59

**Question:** [Chapter 4 - Process Synchronization] Why does sharing data across threads require less overhead than Inter-Process Communication (IPC)?

**Answer:** Threads can access shared process memory directly. Processes generally need an IPC mechanism, although shared-memory IPC can also avoid repeated copying; synchronization is needed in either case.

---

## Card 60

**Question:** [Chapter 4 - Process Synchronization] In modern browser architecture, what responsibilities are typically assigned to a renderer's main thread versus worker threads?

**Answer:** The main thread handles JavaScript execution and page layout; worker threads execute asynchronous background tasks.

## Card 61

**Question:** [Chapter 3] What is the usual memory hierarchy, from fastest/smallest toward slowest/largest?

**Answer:** CPU registers → CPU caches → main memory (RAM) → secondary storage. Faster levels generally cost more per byte and have less capacity.

---

## Card 62

**Question:** [Chapter 3] How do cache and RAM differ?

**Answer:** Cache is smaller and faster and holds copies of recently or frequently used data/instructions. RAM holds the working memory of active programs.

---

## Card 63

**Question:** [Chapter 3] What is contiguous memory allocation?

**Answer:** Each process occupies one continuous region of physical memory. Fixed and variable partitioning are examples.

---

## Card 64

**Question:** [Chapter 3] How does internal fragmentation differ from external fragmentation?

**Answer:** Internal fragmentation wastes space inside an allocated block. External fragmentation leaves free space scattered between allocated regions.

---

## Card 65

**Question:** [Chapter 3] How do pages and frames differ?

**Answer:** Pages are fixed-size units of a process virtual address space; frames are same-size units of physical memory. A page table maps pages to frames.

---

## Card 66

**Question:** [Chapter 3] How do paging and segmentation differ?

**Answer:** Paging uses fixed-size blocks; segmentation uses variable-size logical regions such as code or stack. Basic paging can cause internal fragmentation; contiguous segment allocation can cause external fragmentation.

---

## Card 67

**Question:** [Chapter 3] How is a logical address split in paging?

**Answer:** Page number = logical address divided by page size, rounded down. Offset = remainder. Physical address = mapped frame number × page size + offset.

---

## Card 68

**Question:** [Chapter 3] Practice: page size 1024 bytes, logical address 2500, page 2 maps to frame 7. Find the physical address.

**Answer:** 2500 = 2 × 1024 + 452. Page = 2 and offset = 452. Physical address = 7 × 1024 + 452 = 7620 bytes. These are additional practice numbers.

---

## Card 69

**Question:** [Chapter 3] What is virtual memory?

**Answer:** An address-space abstraction that lets the OS map a process logical addresses to physical memory; demand paging can keep only needed pages in RAM and use backing storage for others.

---

## Card 70

**Question:** [Chapter 3] What is a page fault?

**Answer:** An access to a page that is not currently resident triggers a trap. For a valid backed page, the OS loads it, updates the mapping and resumes; an invalid access must be handled as an error.

---

## Card 71

**Question:** [Chapter 3] What is thrashing?

**Answer:** Excessive paging in which the system spends much of its time moving pages rather than doing useful execution, often because active working sets exceed available frames.

---

## Card 72

**Question:** [Chapter 3] Practice: a segment has base 2500 and limit 600. Is offset 600 valid?

**Answer:** No. When limit is the segment length, offsets must satisfy 0 ≤ offset < 600. Offset 599 is valid; offset 600 is outside the segment.

---

## Card 73

**Question:** [Chapter 4] What is the ownership difference between a mutex and a semaphore?

**Answer:** A mutex has an owner, which must release it. A semaphore represents permits and signaling; a different thread may signal it, subject to the API and program design.

---

## Card 74

**Question:** [Chapter 4] What does a condition-variable wait do?

**Answer:** It atomically releases the associated mutex and blocks. Before returning it reacquires the mutex; check the shared-state predicate again in a while loop.

---

## Card 75

**Question:** [Chapter 4] Why is a condition variable different from a counting semaphore?

**Answer:** A semaphore retains a permit count. A condition-variable notification is not a stored permit; shared state records whether a condition is satisfied.

---

## Card 76

**Question:** [Chapter 4] How does ordering resource acquisition prevent deadlock?

**Answer:** Require all threads to acquire resources in the same global order. This breaks circular wait, one of the four necessary deadlock conditions.
